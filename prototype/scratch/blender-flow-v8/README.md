# Zibloo v8：柔软腕根与全身协调

可丢弃的动作原型，用来判断八腕近端与躯干连接处是否足够柔软、活泼。v7 的末端活动和眼神已有改善，但用户仍指出腕根僵硬；因此本轮改变近端变形方式，而不是单纯增大末端波幅。

## 参考与改变

[真实章鱼和动画制作参考](../../../docs/brand/3d/octopus-motion-research.md)。真实章鱼的腕足是连续可变形的肌肉结构；Hank 的制作访谈则提示每拍保留两三条主动作腕，避免八腕同时抢走眼神的注意力。

- 新增 `Crown` 软组织骨骼，接替连接躯干与腕足的中央固定权重，随动作倾转和位移。
- 从每条腕足的第一段就开始宽幅弯曲，弯曲错拍传向末梢；八个附着点也随软组织移动。
- 问候由主腕引导，邻腕收敛，后腕错拍平衡；不同腕足保持不同活动强度。
- 托珠末端保留任务位置，近端继续调整；保留四动作、眼神、立体厚度及四种变色。

预览有正、侧、背面、眼神特写、动作进度条；另提供腕根正背面图、v7/v8 动作对照 GIF。GIF 是抽帧示意，连续动作以网页 GLB 为准。

## 生成与验证

沿用已获授权的公开仓库 GitHub Actions 免费 Ubuntu runner，Blender 4.5.3 LTS、CPU 两线程。本机仅编辑代码、下载结果和轻量拼图。

云端检查包括：所有八腕第一段相对躯干的方向变化、逐帧旋转连续性、皮肤权重、循环闭合、Blender/GLB 对齐、手机取景、眼神与变色。数值通过不等同于动作体验获得用户认可；须结合渲染帧检查腕根夹折、相互遮挡与动作节奏。

工程保留源形、自动 QuadriFlow 控制笼与烘焙骨骼。正式制作仍需人工整理腕根拓扑、接触控制及局部组织形变；本轮不是生物肌肉模拟。

[云端模型与动作检查](https://github.com/kikoiio/Zibloo/actions/runs/40056892443)，模型提交 `645c9c69282287385d21c8225b2384d579b93188`。

[最终网页与变色画面检查](https://github.com/kikoiio/Zibloo/actions/runs/40057948773)复用同一组模型和渲染，检查脚本提交 `100177d1307fd3d80195e640ff367dd663deb89c`。

3,791 面控制笼、15,166 个运行时身体顶点、104 根骨骼。优化 GLB 977,900 字节（约 955 KiB）。侧面体积保持，头部取样带深宽比约 1.20。

| 动作 | 八腕近端相对躯干的方向变化范围 | 最大单帧腕足转角 |
| --- | --- | --- |
| Idle | 21.2–50.5° | 3.92° |
| Greeting | 26.6–65.0° | 11.21° |
| Focus | 18.4–39.0° | 3.04° |
| Celebrate | 33.5–82.0° | 15.97° |

这些数值是运动方向变化的观察，不代表生物关节角度。v7 待机近端仅约 0.18–0.26°；v8 待机八腕均有约 21–50°，数据见 `output/arm-base-comparison.json`。

- 全骨骼首尾局部矩阵最大差约 2.99e-7；实际网页表面循环首尾最大差约 0.000238 模型单位。
- Blender 与优化 GLB 的 96 个参照点最大误差约 0.00231；皮肤权重归一误差小于 4.6e-8。
- 暂停姿势与切换中拖动进度条误差为 0；眼睛相对头部的眨眼、眯眼、笑眼和单眼眨眼检查通过。
- 手机每动作检查 24 个时刻，最大水平/垂直投影约 0.805 / 0.513，均在取景内。四配色、渐变、演示返回/停止和减少动态效果检查通过。

已目视复核四组动作全部 64 张渲染帧，以及腕根正背面近景、真实侧面、四种眼神与手机画面。腕足的出发方向随相位改变，近端扇开与回收比 v7 清楚；问候仍由主腕引导，庆祝先收拢后展开，托珠保持较安静的任务姿态。

背面颈腕交界仍有褶痕；休止轮廓仍保留原来的中央放射布局。这轮改善的是近端活动和协调，并没有完成根部结构重设计或生产级拓扑。技术检查通过不等同于用户已认可动作的活泼程度。

本地预览：<http://localhost:4323/>。建议先比较“招手问候”和“欢愉达成”，再从正、侧、背面拖动进度查看腕根。`output/motion-comparison.gif` 是同相位的 v7/v8 抽帧对照；工程与模型校验值见 `output/provenance.json`。
