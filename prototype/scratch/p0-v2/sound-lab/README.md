# Zibloo 声音探索 01—08

独立试听页：`http://127.0.0.1:4318/sound-lab/index.html`。不自动播放，也不替换计时器当前临时提示音。可从原型顶部或设置进入。

| 编号 | 方向 | 表达重点 |
| --- | --- | --- |
| 01 | 潮汐泡泡 | 有机水泡滑音，更接近海洋角色发声 |
| 02 | 温柔咕噜 | 无词元音式拟声，圆润、亲近 |
| 03 | 水光玻璃 | 玻璃非整数泛音，清透、克制 |
| 04 | 海岸木音 | 木质短敲击，自然、有节奏 |
| 05 | 小小电波 | 柔和调频电子音，灵巧、有回应感 |
| 06 | 浮游气息 | 轻哨加滤波气息，安静、舒缓 |
| 07 | 暖弦涟漪 | 拨弦衰减与共鸣，温暖、音乐感 |
| 08 | 跃动节拍 | 更鲜明的中频合成打击，偏训练场景 |

每组 4 段：开始工作（短促上扬）、进入休息（较慢下行）、全部完成（展开收束）、日常提醒（两次呼唤，中间留白）。另有每组按上述顺序串联的完整试听，共 40 个 WAV。无词角色声音与系统真人语音播报分开讨论；不以某种真人声线作为角色身份。

当前是原创程序合成的风格草稿，没有采样真人、现成品牌音效、外部素材或音频生成服务。不要把草稿当作最终声音商标。先选音色，再调整亲近感、起音、节奏、尾音、响度，最终把选中的方向做成可选预设，并保持同一套情绪语法。

试听页：原生单一音频播放器、完整试听、按事件横向比较、停止并取消队列、候选本地保存与复制。候选不会上传；刷新计时器也不会应用这些音色。未做 Android 后台提醒。

## 素材与复现

- `manifest.json`：音色、情绪事件、文件映射，供后续预设接入。
- `audio/`：44.1 kHz、16-bit、单声道 PCM WAV，32 个事件文件和 8 个串联文件。
- `generate.py`：确定性 DSP 生成源；`python3 generate.py`，需要 numpy。
- `audio-checks.json`：32 段的长度、样本峰值及整体 RMS。使用近似有效段 RMS 对齐，同时把样本峰值限制在 0.72；这不是感知响度/LUFS 精确匹配，不承诺同样响。静音间隔与音色不同也会影响整体 RMS。

当前文件长度约 1—2.4 秒，串联约 8 秒。技术校验覆盖可解码、非静音、未削波；不会替代人工对情绪、舒适度、手机扬声器和嘈杂环境的试听。未在本机启动 GUI 自动化。

## 计时提醒修复

原先快捷/专注 Start 未创建或恢复 AudioContext；第一次发声可能延迟到定时器回调，无法稳妥满足浏览器自动播放策略。现在在真实开始/继续点击中启用音频，播放前等待恢复，失败显示提示。参见 [Chrome 自动播放策略](https://developer.chrome.com/blog/autoplay/)。

训练“关闭引导”仅关闭训练阶段切换；不再误屏蔽快捷/专注和完成提醒。全局静音仍关闭所有提示。保留原临时声音，完成提示略延长和增强；新候选暂不设为默认。
