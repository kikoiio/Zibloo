# Zibloo 产品需求文档（PRD）

## 1. 产品意图

**Zibloo** 是一款计时器应用。它不是「带吉祥物的计时器」,而是「一只陪你计时的章鱼」:Zibloo 是产品的灵魂、导航的载体、声音的签名和品牌的全部。

- **角色定位**:Zibloo 是角色化陪伴。它有状态、有反应,用户计时时它就在场;用户的坚持会让它变得更生动。
- **品牌扩展**（2026-10-22）：用户提出未来可能扩展到计时器之外；角色与品牌标志不固定绑定秒表或时钟。本次不扩大首版功能范围。
- **产品形态**:安卓 App + 网页版;主页是 Zibloo 的生活场景,三个计时领域是它的三种「工作模式」。
- **核心场景**:
  1. 间歇训练(HIIT):跟练时不用盯屏幕,靠叫声知道当前段
  2. 专注工作(番茄钟):Zibloo 安静陪伴
  3. 生活提醒(吃药、喝水等):Zibloo 跳出来叫你
- **用户**:大众用户,无特定限制;开发者本人是第一用户。
- **非目标(首版)**:不做云账号、不做 iOS(架构预留)、不上架应用商店(架构预留)、不做养成经济系统(喂食/货币/数值成长)。

## 2. Zibloo 角色系统

### 2.1 世界观(叙事基准)

Zibloo 悬浮在主页的海底小窝中。用户使用计时器,就是在让 Zibloo「工作」:陪你训练、陪你专注、帮你记事。它的状态由当前计时活动实时驱动,它的样子随用户的坚持慢慢变得丰富。

### 2.2 状态映射(P1)

Zibloo 的表现是当前活动状态的纯映射,无持久数值。同一状态在 UI 上表现一致。

原型提案(2026-10-21,待评审):加入眨眼与触手动作,以章鱼变色为角色特色。待机浅水绿、训练珊瑚橙、专注沙金、提醒天蓝、庆祝草绿;不使用紫色。专注和暂停时减少动作,系统或应用开启减少动态效果时显示静态姿态。此段为原型探索,不是用户已确认的最终颜色映射。

2026-10-22 更新：用户已选择 B2 角色造型与 C3 品牌组合方向（见 §6），要求腕足自然、灵活，能够主动伸展、回卷、触碰与拿放物件。具体连续动作及各活动颜色映射仍待验证；旧八帧动作不能作为新角色动作验收依据。

| 状态 | 触发条件 | 表现方向 |
|---|---|---|
| 待机 | 无计时活动 | 在小窝里漂浮、眨眼、吐气泡,可点按互动(叫声 + 小动画) |
| 训练陪伴 | 间歇训练运行中 | 随段切换加油(运动段)或放松(休息段),呼应叫声语义 |
| 专注安静 | 番茄钟运行中 | 收起触手安静陪伴,不打扰;进入休息时苏醒伸展 |
| 提醒召唤 | 提醒触发时 | 跳出、醒目动作 + 叫声 + 震动 |
| 庆祝 | 任意计时完成 | 欢快动作 + 欢快三连叫声 |

- 状态映射必须在锁屏/后台时降级为通知呈现(通知图标与文案沿用状态语义),不做后台动画。
- 今日陪伴统计(P1):记录「今天 Zibloo 陪你专注/训练了多久」,在主页与历史展示。

### 2.3 轻养成(P2)

- 连续使用/完成目标解锁纯视觉内容:姿态、装饰(如帽子、气泡道具)。
- 断用后 Zibloo 回到基础状态(已解锁内容保留,仅当前展示回落),不惩罚、不丢失。
- 不做喂食、货币、等级、能力解锁等经济系统;解锁条件仅基于本地使用数据。

### 2.4 听觉签名

- 默认提示音为 **Zibloo 叫声**:合成的「啵噜啵噜~啾↑」气泡音(现实中章鱼不发声,为品牌原创)。
- 叫声有语义,训练时不用看屏:
  - 运动开始 = 两声上扬(精神)
  - 休息开始 = 两声下沉(柔和)
  - 完成 = 欢快三连
- 叫声预设(2026-10-24 定):默认 E「灵巧啾噜」,设置可切换 G「清透轻呼」或静音;十段 WAV 已随应用资产分发(`static/sounds/`,含哈希清单)。更正式的音频设计仍可后续替换(见 §9)。

## 3. 信息架构

### 3.1 结构总览

```
底部导航:小窝(主页) · 历史 · 设置
小窝(章鱼即主页)
 ├─ Zibloo 本体:点按 → 互动反应(叫声 + 小动画,不承担导航)
 ├─ 触手/气泡即入口:三条触手(或周围气泡)分别指向三种工作模式
 │   ├─ 训练模式(间歇训练)
 │   ├─ 专注模式(番茄钟)
 │   └─ 记事模式(定时提醒)
 ├─ 快捷计时:1/3/5/10 分钟快速倒计时(小气泡入口)
 └─ 问候语(按一天时段变化)
运行页(任一模式计时中,全屏)
 └─ Zibloo 按 §2.2 状态出现,叠加各模式的计时信息
```

- **交互原则**:章鱼有互动反应,但功能入口一律有明确的可点目标(触手/气泡),不强迫用户与角色互动才能使用功能。
- **可发现性**:三种工作模式入口在主页同时可见,不藏进弹层。
- 通知图标等系统级触点使用 Zibloo 形象(素材规格见 §9 待定项)。

### 3.2 训练模式(间歇训练)

| 功能 | 说明 |
|---|---|
| 基础循环 | 运动时长 + 休息时长 × 组数,均可调(步进器) |
| 预设模板 | 内置经典 30/15×8、Tabata 20/10×8、力量 40/20×6、耐力 60/30×4;选中模板后参数联动 |
| 语音/提示音引导 | 三档:语音播报 / 仅叫声提示 / 关 |
| 组数与下段预览 | 运行页显示「第 N / M 组」和下一段是什么、多长 |
| 运行控制 | 暂停/继续、跳过当前段、结束 |
| 到点提示 | 每段切换按语义播放叫声(见 §2.4) |

二期(暂不做,界面预留):多段自定义序列(热身、自定义段名)。

### 3.3 专注模式(番茄钟)

| 功能 | 说明 |
|---|---|
| 基础番茄钟 | 专注时长可选(15/20/25/50 分),短休息(3/5/10 分),结束提醒 |
| 长休息循环 | 每 N 个番茄(默认 4)进入长休息,长休息时长可调(默认 15 分) |
| 今日统计 | 今日番茄数、今日专注总时长、连续天数 |
| 任务标签 | 预设标签(读书/工作/学英语/编程)+ 自定义标签;每段专注可打标签 |
| 运行界面 | 圆环倒计时 + 标签 + 第几个番茄 + Zibloo 专注状态 |

### 3.4 记事模式(定时提醒)

| 功能 | 说明 |
|---|---|
| 一次性提醒 | 快捷设置「X 分钟/小时后提醒我」;指定时刻的一次性提醒 |
| 每日固定 | 每天固定时刻(如 08:30 吃药) |
| 周期重复 | 每周指定星期几(周一/三/五 19:00);每 X 小时区间重复(喝水类) |
| 重启后仍生效 | **硬性要求**:手机重启后所有提醒继续生效,不允许丢失 |
| 提醒列表 | 名称、时间规则、启用开关;新建/编辑/删除 |
| 提醒方式 | 响铃 + 震动 + 可选语音播报(默认全开,可单条配置) |

### 3.5 历史

| 功能 | 说明 |
|---|---|
| 完整历史 | 每次训练/专注/提醒的记录:类型、开始时间、时长、完成度(完整/提前结束/跳过组数)、标签 |
| 图表 | 周专注时长柱状图、周环比(如 +18%)、今日陪伴统计(§2.2) |
| 筛选 | 按类型筛选:全部 / 训练 / 专注 / 提醒 |
| 数据存储 | 本地存储,无账号;支持导出 |

### 3.6 设置

- 语言:中文 / English(首版即双语,见 §7)
- 提示音:默认 Zibloo 叫声,可选清脆、静音等
- 震动强度:轻 / 标准 / 强
- 语音播报:开 / 关
- 数据:导出
- 关于:版本信息

## 4. 非功能需求

### 4.1 可靠性(最高优先级)⭐

- 锁屏或切后台时,计时进行中倒计时不暂停、不漂移;到点准时提醒。
- 杀掉 App 后,已设置的提醒依然到点触发(本地通知/闹钟级调度,不依赖 App 存活)。
- 重启后提醒规则不丢(见 §3.4)。
- **验收标准:以上三条必须在真机(安卓)上人工验收通过,模拟器结果不算数。**
- 角色状态降级规则见 §2.2:后台不做动画,不影响可靠性。

### 4.2 平台与技术

- 双端交付:安卓 App(APK 直接下载,官网/GitHub Releases 免费分发)+ 网页版,同一套代码。
- **技术选型待架构阶段重评**:章鱼即主页意味着更高的角色渲染与动画要求。Capacitor + Web 栈是候选而非硬约束;架构阶段须评估动画/渲染方案(含 Zibloo 状态系统的实现路径)后定稿。暂不上架 Google Play,但技术方案须满足以后上架的条件(如 target API 34+)。暂不做 iOS,架构不排斥未来扩展。

### 4.3 质量与流程

- 自动化测试:计时逻辑、提醒调度逻辑、**Zibloo 状态映射逻辑**必须有单元测试;UI 按可行程度覆盖。
- 分里程碑交付,每个里程碑交付可看/可装的东西,由用户适时验收,避免大返工。
- 开发过程中多次向用户展示效果,不等到交付才暴露问题。
- 代码按 skill 流程做 code review。
- GUI 自动化验证优先云端/CI,本机受资源规则约束;最终可靠性验收必须真机。

## 6. 品牌规范

### 6.1 视觉（已选 B2 角色与 C3 品牌方向）

- **用户决定(2026-10-21)**:选择 A「场景小窝」继续,禁止紫色。此决定覆盖原有蓝紫配色,包括界面与角色。
- **用户决定(2026-10-22)**:选择 B2 作为主角色造型方向、C3 作为角色与字标的品牌组合方向。保留修长流动的腕足、青绿/浅薄荷双配色、简洁眼睛与克制表情；弱化玩偶感，避免生物写实和令人不安的细节。[完整选择记录与参考图](brand/selected-direction.md)。具体色值、主用组合和正式素材仍待细化。
- **主色提案(待评审)**:海盐蓝/青蓝(#24818e),按钮与进度使用青蓝渐变(#287d89 → #216d79)。
- **背景提案(待评审)**:浅水绿白(#f0f8f7),白色卡片 + 低饱和青色阴影。
- **模式色提案(待评审)**:训练=青蓝、专注=珊瑚橙、记事=天蓝;保留模式可辨性,不使用紫色。
- **成功/休息色**:青绿(#59c2a0);危险:#ff6b81
- 圆角卡片(24px 级)、大圆角按钮、气泡点缀元素
- Logo:按已选 C3 的小写「zibloo」字标与角色组合方向细化，字形和矢量轮廓尚未定稿。
- P0 交互原型已退役(2026-10-24);B2 五姿态帧与 C3 原字标排版已迁移至应用静态资产(`static/zibloo/`),腕足构图允许自然遮挡,不要求八条同时展开。桌面保留错落入口,手机在角色下方排列三入口。

### 6.2 吉祥物素材

- 形象:以已选 B2 为基准，修长柔软的腕足与 S 形流线、圆钝末端、简洁眼睛、青绿与浅薄荷双配色；悬浮水中，腕足可主动互动，不固定手持秒表。身体和界面继续禁止紫色。
- 素材方向(2026-10-24 更新):以 B2 原图为基准的五张对齐姿态帧(四帧划水循环 + 一帧抬爪)已随 P1 应用资产分发;不使用 3D、模型或骨骼,整图仅做轻悬浮。独立腕足动作、分层与矢量化不作为 P1 前置。旧页面的大头短腕足素材和八帧动画不作为已认可形象或动作依据。
- P2 视觉解锁所需额外素材在 P2 前定稿。

### 6.3 文案基调

- 产品叙事围绕 Zibloo 展开(「陪你」视角),文案避免拟人过度导致功能含义不清;功能文案优先准确,角色语气为辅。

## 7. 本地化

- 首版支持中文 + English 双语,代码从第一天起按 i18n 结构组织(文案不硬编码)。
- 所有用户可见文案(含 Zibloo 状态相关文案)进语言资源文件。
