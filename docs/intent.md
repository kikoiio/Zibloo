# Zibloo 产品意图

Zibloo 是一块个人发现看板。打开网页即可浏览跨社区的新项目,按用途搜索、保存感兴趣的发现,并使用一个简单计时器。章鱼留在顶栏,用功能不用先点它。

当前实现见 [`architecture.md`](architecture.md)。当前只开发和维护网页端;其他平台开发已暂停。

## 谁、场景、非目标

- **用户**:开发者自己。
- **形态**:浏览器中的网页应用。
- **打开之后**:
  1. 各社区 trending 收成卡片,混合排在同一信息流里,来源作为卡片标签
  2. 在看板顶端的计时工具条设置分钟数并启动单个倒计时,可暂停、继续或结束
- **这版不做**:训练模板、专注循环、多张计时卡片、五列判断、侧栏、日报、观察名单、热点设置、来源筛选芯片。
- **已不做**:提醒 / 记事。看板只留计时与热点。
- **平台范围**:当前只做网页端;其他平台的开发和发布暂停。
- **仍不做**:云账号。

## 看板

主界面是一条跨来源发现流。收取把 GitHub、Hacker News、Lobsters、Hugging Face、GitLab、crates.io、DEV、Flathub、Product Hunt、X 的今日榜拉成卡片;来源只标在卡片上,不作为分组或筛选条件。可以搜索标题、简介、来源、语言和个人笔记,按首次发现时间或各来源榜单位置排序,并将条目收藏到「已收藏」。榜单位置只在各自来源内有意义,不同来源的星标、点赞、下载量也不作横向比较。点开卡片可查看历史、写笔记或打开原始页面。收取仍是手点,始终拉全部来源。AI 自动评估和筛选项目留到后续;GitHub token、周榜语言分榜这版不做。

看板顶端的计时工具条提供一个可调时长的倒计时器,默认 25 分钟。运行时显示剩余时间,可暂停、继续或结束;完成后记录历史。计时器留在看板上,不进入单独的运行页。没有单独的训练、专注、历史、设置页。

## 可靠性

1. 进行中的倒计时由锚点时间推导,不把剩余秒数写进存储。暂停期间不走字。
2. 页面运行且可见时,计时段边界播放提示音。
3. 浏览器可能降低后台页面的计时精度;页面关闭后不会触发计时提示。

## 验收

| # | 标准 |
|---|---|
| V1 | 打开即跨来源发现流,来源作为卡片标签;可搜索、排序、收藏;计时器可调时长 |
| V2 | 没有侧栏、日报、五列并排分栏 |
| V3 | 看板只有一个可调时长的计时器,支持开始、暂停、继续和结束 |
| V4 | 章鱼在看板上,功能不依赖点它 |
| V5 | 计时投影、热点合并、状态映射仍有单元测试 |
